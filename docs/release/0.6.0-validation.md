# Cortex 0.6.0 validation record

Review date: 2026-11-25. Application `0.6.0`, behavioral model `3.0.0`, feature
schema `support-features-v3.0.0`. This record separates what was measured,
what was run on a real Mac, and what was not checked. It describes a local
ad-hoc build; it is not a signed, notarized public release.

## What changed and how it was checked

- **Camera physiology is an input to the support rules.** Heart rate and SDNN
  were compared with ECG on a public video set; breathing rate with simulated
  truth. The method, every figure and the limits are in the
  [qualification report](../research/physiology-qualification.md); the
  decision is [ADR 0008](../adr/0008-qualified-camera-physiology.md). The
  agreement comes from one participant, and the estimator published nothing
  for the two participants with intermediate and dark skin tone.
- **The rules stay behavior-led.** Tests assert that with no camera, no face,
  no pulse or no personal reference every score equals the behavior-only
  score; that physiology is mixed only into a state whose own behavior rule is
  eligible; that no state whose behavior score is below the entry threshold is
  raised; that blink rate and eye-closure share count only beside a usable
  heart rate or SDNN; that a published heart rate needs a confirmed harmonic
  signal-to-noise window; that a breathing rate needs head movement and a
  pulse-derived channel to agree; that no variability value outlives the
  pulse by more than ten seconds; and that nothing is published on
  signal-free input.
- **An end-to-end seam test** drives a simulated color trace through the
  production processor, feature fusion, the personal reference and the
  physiology block. It found that two pulse-derived breathing channels could
  agree on a wrong rate and have it published; the gate was changed.
- **Two audit rounds** fixed defects in the daemon and in the three clients,
  each with a regression test. They are listed in the
  [changelog](../../CHANGELOG.md).
- **One independent review round** read the finished change cold. It found
  that camera evidence could lift a weak behavioral reading past the entry
  threshold, that blink and eye-closure values moved scores with no pulse,
  that the last SDNN was re-published after the pulse was lost, that a break
  could be offered to an empty chair, and that several documents claimed more
  than had been measured. Each was fixed with a test and the documents were
  corrected; the changelog lists them under "Found by an independent review".
  Both qualification runs were repeated on the corrected code, and the
  figures in this release are from that repeat.
- **The packaged app was installed and used** on the review Mac. That run
  found a crash and several presentation defects, described below.

Defects the first run found, all fixed in this release with tests where a test can
reach them:

- **Ending a session and starting another crashed the app.** pynput's keyboard
  listener thread read the keyboard layout through HIToolbox, which traps off
  the main thread on current macOS. The listener now skips a read its
  listening path never uses.
- The session report, multi-day trend and coding-practice coach were still
  given RMSSD, which did not qualify. They receive SDNN.
- The camera prompt described the camera's purpose as monitoring focus and
  attention. It now says what is estimated and that frames are not saved or
  sent.
- Camera-offline guidance sent the user to a System Settings list that does
  not contain an app that was never asked.
- Pause stayed enabled beside "Session ended".
- **A camera that was still starting was reported as offline.** For the twelve
  seconds the camera and the face model take, at every launch and again right
  after the permission was granted, the dashboard and the browser popup said
  "Camera offline — open Settings to allow camera access". The three earlier
  passes had each taken their first screenshot after that window. The daemon
  now marks a start in flight and both clients say "Starting camera…".

## Not verified

- **Accessibility permission.** macOS asks for Touch ID or the account
  password before the switch can be turned on, and the review did not have
  either. Keyboard features, and therefore a support estimate from real
  typing, were not exercised on the installed build. Mouse and window-focus
  telemetry were live.
- **A reading from a real face.** Nobody sat at the camera during the run, so
  no live pulse, variability, breathing rate, personal reference or strain
  load was observed on the installed build. Those paths are covered by the
  qualification replay, which runs the same capture and physiology code, and
  by the seam and wiring tests.
- **The break pill on the installed build.** The dashboard changes made after
  the first live run (the break pill's lifetime and wording) need a strain
  load, and therefore a face, to appear. They are covered by Qt tests only.
  History with recorded sessions, the Quit button and repeated end/start
  cycles were exercised on the earlier builds and not again on the last one.
- **Browser and editor extensions against the installed app.** Both were built
  and tested; neither was connected to the running app, because installing
  the native-messaging manifest needs a full browser restart.
- **Intel, notarization, VoiceOver.** The Python gate ran on a hosted Intel
  runner. No Intel build of the app was made or run, and no Developer ID
  signature, notarization or assistive-technology session was performed.

An ad-hoc signature changes with every build, so macOS treats a rebuilt app as
one that never asked for the camera. A Developer ID signature does not have
this property.

## Release boundary

The `v0.6.0` tag (commit `9ed4ac1`) ran the signed release workflow on
2026-11-26 (run 45861404959, after the tag was re-created on the corrected
history; the first run, 45847786520, ended the same way). Its pre-release gate
passed on `macos-15`. The signing job then stopped at credential validation:
Apple answered HTTP 403, "A required agreement is missing or has expired", as
it had for v0.5.0 and v0.5.1. No DMG was signed and no draft release was
staged. The Apple Developer Account Holder must accept the team's current
agreements; re-running the failed jobs of run 45861404959 then builds from the
same tag. Public promotion
continues to require the existing
[release evidence and assurance protocol](README.md). A successful source gate
or ad-hoc DMG is not a public-release authorization.

## Scientific and operational limits

The reference comparison covers one participant, one camera and one room, with
no held-out data; the estimator abstained on the two participants with
intermediate and dark skin tone, including bright-light windows of one of
them in which the pulse was mostly readable; breathing rate has no reference
sensor behind it, and blink rate and eye-closure share were not checked
against anything; and no study connects any of these values, or the fused
score, to a need for support. Camera physiology corroborates the behavior
rules and cannot establish a state by itself. The product remains an alpha
research prototype with `suggest_only` as its default.

Dependency audits enforce dated exceptions rather than claiming zero risk.
See the [model card](../model-cards/deterministic-support-v3.md),
[limitations](../limitations.md) and [release guide](README.md).
