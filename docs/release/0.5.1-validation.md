# Cortex 0.5.1 validation record

Review date: 2026-10-11. Application `0.5.1`, behavioral model `2.6.0`, feature
schema `support-features-v2.2.0`. This record distinguishes source verification
and local packaging from a signed, notarized public release.

## Correctness and resilience

- Behavioral smoothing now accounts for elapsed monotonic time. At the normal
  500 ms cadence the weight remains 0.3; at other cadences it is
  `1 - (1 - 0.3) ** (elapsed_seconds / 0.5)`. Constant observations therefore
  converge at the same rate across sampling cadences. Duplicate/regressed
  timestamps cannot earn updates or dwell, boot changes reset continuity, and
  gaps above three seconds reset smoothing and telemetry warmup. This is an
  engineering correction, not evidence of cognitive-state accuracy.
- Feature schemas reject NaN and infinity before serialization. Fusion rejects
  non-finite time and does not let reordered observations overwrite newer data.
  API validation errors retain useful field locations without reflecting the
  rejected input; even malformed non-finite input produces a stable 422 response.
- An oversized native-messaging prefix is rejected without draining an
  attacker-specified body. The former drain could hang indefinitely while the
  sender held stdin open. Truncated headers/payloads fail explicitly, and the
  dependency-free failure response does not disclose exception details.
- Desktop and browser pulse estimates have matching finite/range checks.
  Desktop readings expire after ten seconds without new state, including when
  the window is hidden. Disconnect and End session clear live diagnostics;
  queued updates cannot repopulate an ended session. The pulse trace displays
  the full accepted range instead of clipping valid readings above 180 BPM.
- The desktop shares its font setup between both launch modes and paints an
  opaque themed background when native window effects are unavailable. Actual
  Qt renders were inspected at 400 × 680 and 380 × 500, including suggestion
  review and stale-state presentation; refreshed README images use synthetic
  data from those renders.
- Release credential setup owns and cleans its temporary Keychain even when
  notarization credential validation fails. Decoded key material is deleted on
  success and every tested failure stage. Tests execute the actual workflow
  shell step against controlled command doubles for both supported credential
  types; they do not use real signing credentials.
- Build provenance resolves pnpm in the extension's project directory using
  the build's Corepack preference. An actual local build exposed a report
  naming global pnpm 12.4.1 even though the extension correctly built with
  pinned 9.15.9; the corrected generator reports 9.15.9. Version probes have
  a bounded timeout, and the release gate explicitly checks the finished
  browser bundle and replay baseline.

## Release boundary

The preceding `v0.5.0` release workflow failed Apple's notarization credential
validation for both architectures with HTTP 403: a required developer-program
agreement was missing or expired. See
[the failed workflow](https://github.com/StevenWang-CY/cortex/actions/runs/38018270373).
Only the Apple Developer Account Holder can resolve that agreement. Local
ad-hoc signing cannot substitute for Developer ID notarization.

The `v0.5.1` tag must run the signed release workflow against the committed
source. Public promotion continues to require the existing
[release evidence and assurance protocol](README.md). A successful source gate
or ad-hoc DMG is not a public-release authorization or a physical-device record.

## Scientific and operational limits

No participant study, reference-sensor comparison, physical camera/TCC test,
VoiceOver session, or independent release review was performed in this source
review. Camera physiology remains optional, experimental, and excluded from
behavioral support inference. Model thresholds remain engineering heuristics;
rate-invariance and synthetic replay do not establish attention, stress,
medical, or real-world productivity accuracy. The product remains an alpha
research prototype with `suggest_only` as its default.

Dependency audits enforce dated exceptions rather than claiming zero risk.
The Intel-specific Protobuf exception expires on 2026-10-15; this review does
not extend it. See the [model card](../model-cards/deterministic-support-v2.md),
[limitations](../limitations.md), and [release guide](README.md) for details.
